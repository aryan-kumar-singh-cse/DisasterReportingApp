# AWS Setup Guide — Crowdsourced Disaster Reporting App

This guide walks you step-by-step through configuring all required AWS services using the AWS Management Console (with AWS CLI alternatives).

---

## Architecture Overview

```text
React/Vite (Amplify Hosting)
        │
        ▼ (HTTPS)
API Gateway (HTTP API: /{proxy+})
        │
        ▼
Single AWS Lambda (`DisasterReportHandler`)
        ├── Amazon DynamoDB (`DisasterReports`)
        ├── Amazon S3 (`disaster-reports-...`)
        └── Amazon Rekognition (`DetectLabels`)
```

## Step 1: Set Up an AWS Budget Alert

> [!TIP]
> Setting up a budget protects your account from unexpected usage and unlocks part of your additional $100 AWS Free Tier onboarding credits.

1. In the AWS Management Console search bar, search for **AWS Budgets**.
2. Click **Create budget**.
3. Select **Zero spend budget** (or **Custom budget** $\to$ Cost budget with a target of **$1.00**).
4. Enter your email address for alert notifications.
5. Click **Create budget**.

## Step 2: Amazon S3 Bucket (Photo Storage)

The S3 bucket stores photos uploaded by citizens. Photos will be uploaded directly from the browser using secure **presigned URLs** generated by your Lambda function.

### 2.1 Create the Bucket
1. Search for **S3** in the console.
2. Click **Create bucket**.
3. Configure the following:
   - **Bucket name**: `disaster-reports-[your-name-or-random-suffix]` (e.g., `disaster-reports-dev-2026`). Note: Bucket names must be globally unique.
   - **AWS Region**: Select the region closest to you (e.g., `us-east-1` or `ap-south-1`). Keep all services in this same region!
   - **Object Ownership**: Leave as **ACLs disabled (recommended)**.
   - **Block Public Access settings for this bucket**: Keep **Block all public access enabled (checked)**.
     *(Security best practice: We don't need public access because the Lambda generates temporary presigned URLs for reading/uploading).*
   - **Bucket Versioning**: Disabled.
   - **Default encryption**: Leave as **Server-side encryption with Amazon S3 managed keys (SSE-S3)**.
4. Click **Create bucket**.

### 2.2 Configure S3 CORS (Crucial for Browser Uploads)
Because the browser uploads photos directly to S3 via presigned `PUT` URLs, S3 must allow cross-origin requests:

1. Click on your newly created bucket name.
2. Go to the **Permissions** tab.
3. Scroll down to **Cross-origin resource sharing (CORS)** and click **Edit**.
4. Paste the following JSON configuration:

```json
[
  {
    "AllowedHeaders": [
      "*"
    ],
    "AllowedMethods": [
      "PUT",
      "GET",
      "HEAD"
    ],
    "AllowedOrigins": [
      "*"
    ],
    "ExposeHeaders": [
      "ETag"
    ],
    "MaxAgeSeconds": 3000
  }
]
```
*(When deploying to production, replace `"*"` in `AllowedOrigins` with your Amplify domain).*
5. Click **Save changes**.

## Step 3: Amazon DynamoDB (Database)

A single table holds report submissions, AI assessments, and community votes.

1. Search for **DynamoDB** in the console.
2. Click **Create table**.
3. Configure the table:
   - **Table name**: `DisasterReports`
   - **Partition key**: `reportId` (Type: **String**)
   - **Sort key**: Leave empty.
   - **Table settings**: Select **Customize settings**.
   - **Capacity mode**: Select **On-demand** (Pay per request — eligible under free tier / credits, zero idle costs).
4. Click **Create table**.

---

## Step 4: AWS IAM Role (Lambda Permissions)

The Lambda function needs permission to read/write DynamoDB, generate S3 URLs / read images, call Amazon Rekognition, and write CloudWatch logs.

1. Search for **IAM** in the console.
2. In the left sidebar, click **Roles** $\to$ click **Create role**.
3. **Trusted entity type**: Select **AWS service**.
4. **Use case**: Select **Lambda**, then click **Next**.
5. Under **Add permissions**, search and select the following managed policies:
   - `AWSLambdaBasicExecutionRole` (allows logging to CloudWatch)
   - `AmazonDynamoDBFullAccess` (or create a custom inline policy for `DisasterReports`)
   - `AmazonRekognitionReadOnlyAccess` (allows `rekognition:DetectLabels`)
6. Also, create an inline policy for S3:
   - Click **Create inline policy** (opens in a new tab or JSON view):
   ```json
   {
     "Version": "2012-10-17",
     "Statement": [
       {
         "Effect": "Allow",
         "Action": [
           "s3:PutObject",
           "s3:GetObject"
         ],
         "Resource": "arn:aws:s3:::disaster-reports-*/*"
       }
     ]
   }
   ```
7. Click **Next**.
8. **Role name**: Name it `DisasterReportLambdaRole`.
9. Click **Create role**.

## Step 5: AWS Lambda Function (Backend Logic)

A single consolidated Lambda function routes requests for fetching reports, generating presigned upload URLs, running AI assessment, and registering community votes.

1. Search for **Lambda** in the console.
2. Click **Create function**.
3. Select **Author from scratch**.
4. Configure:
   - **Function name**: `DisasterReportHandler`
   - **Runtime**: **Node.js 20.x** (or **Python 3.12**)
   - **Architecture**: `x86_64` (or `arm64`)
   - **Change default execution role**:
     - Select **Use an existing role**.
     - Choose `DisasterReportLambdaRole` created in Step 4.
5. Click **Create function**.

### 5.1 Set Environment Variables
1. Go to the **Configuration** tab $\to$ **Environment variables** $\to$ click **Edit**.
2. Add the following key-value pairs:
   - `TABLE_NAME` = `DisasterReports`
   - `BUCKET_NAME` = `[your-s3-bucket-name]`
3. Click **Save**.

### 5.2 Adjust Timeout & Memory
1. Go to **Configuration** $\to$ **General configuration** $\to$ click **Edit**.
2. Increase **Timeout** from 3 seconds to **15 seconds** (Rekognition calls usually take 1–3s; a 15s timeout prevents premature aborts).
3. Leave memory at **128 MB** or **256 MB**.
4. Click **Save**.

## Step 6: Amazon API Gateway (HTTP API)

We use an HTTP API (lightweight, cheaper, and lower latency than REST APIs) with a single proxy route.

1. Search for **API Gateway** in the console.
2. Locate **HTTP API** and click **Build**.
3. Under **Create an API**:
   - **API name**: `DisasterReportAPI`
   - Click **Next**.
4. Under **Configure routes**:
   - Method: `ANY`
   - Resource path: `/{proxy+}`
   - Click **Next**.
5. Under **Define stages**:
   - Stage name: `$default` (Keep **Auto-deploy** enabled).
   - Click **Next** $\to$ **Create**.

### 6.1 Attach the Lambda Integration
1. In the API Gateway menu on the left, click **Integrations**.
2. Select the `ANY /{proxy+}` route.
3. Click **Create and attach an integration**.
4. Integration type: **Lambda function**.
5. Select your Lambda function: `DisasterReportHandler`.
6. Click **Create**.

### 6.2 Configure CORS in API Gateway
1. In the left menu, click **CORS**.
2. Click **Configure**.
3. Set the following:
   - **Access-Control-Allow-Origin**: `*` (or your frontend domain)
   - **Access-Control-Allow-Headers**: `*` (or `Content-Type, Authorization`)
   - **Access-Control-Allow-Methods**: `GET, POST, OPTIONS`
4. Click **Save**.

### 6.3 Copy the Invoke URL
- From the API Gateway overview page, copy your **Invoke URL** (e.g., `https://abc123xyz.execute-api.us-east-1.amazonaws.com`).
- This will be set as `VITE_API_URL` in your frontend configuration.

## Step 7: AWS Amplify Hosting (Frontend Deployment)

Deploy the React + Vite static single-page application.

1. Search for **AWS Amplify** in the console.
2. Scroll to the bottom and click **Amplify Hosting** $\to$ **Host web app**.
3. Choose your deployment source:
   - **GitHub / GitLab / Bitbucket**: Continuous deployment upon git push (recommended).
   - Or **Deploy without Git provider**: Drag and drop your `frontend/dist.zip` directly.
4. **App settings**:
   - App name: `disaster-report-frontend`
   - Build settings (if using Git):
     ```yaml
     version: 1
     frontend:
       phases:
         preBuild:
           commands:
             - cd frontend && npm ci
         build:
           commands:
             - npm run build
       artifacts:
         baseDirectory: frontend/dist
         files:
           - '**/*'
       cache:
         paths:
           - frontend/node_modules/**/*
     ```
5. **Environment Variables in Amplify**:
   - Add variable: `VITE_API_URL` = `https://[your-api-gateway-invoke-url]`
6. Click **Save and deploy**.

## Verification & Sanity Check

Once configured, verify your setup against these 4 checks:

1. **Lambda Health Check**: Test your Lambda via API Gateway in a terminal:
   ```bash
   curl https://[your-api-id].execute-api.[region].amazonaws.com/health
   ```
   Should return HTTP 200 with JSON response.
2. **S3 Presigned URL Test**: Request a presigned URL and verify `curl -X PUT --upload-file test.jpg "[presigned-url]"` completes with 200.
3. **Rekognition IAM Check**: Ensure the Lambda execution role has `AmazonRekognitionReadOnlyAccess`.
4. **DynamoDB Write Check**: Submit a test report and confirm the row appears in the DynamoDB console under **Explore items**.
